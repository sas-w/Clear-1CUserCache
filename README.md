# Очистка пользовательского кэша 1С

## Графическая версия EXE

**Clear-1CUserCache.exe** — основной вариант с отдельным окном. Пользователю нужен
только этот файл. Запуск — двойным щелчком под своей учётной записью, без повышения прав.
Приложение на C# / WinForms, без запуска PowerShell, временных скриптов и консоли.
Manifest содержит `requestedExecutionLevel="asInvoker"`.

По умолчанию открывается компактное окно 570 × 330: пользователь, основное
сообщение, прогресс и кнопки. Каталоги и журнал скрыты под ссылкой «Подробности»;
она разворачивает окно, а «Скрыть подробности» возвращает компактный вид.
Размеры указаны при масштабе Windows 100%. При открытой 1С очистка недоступна: закройте её и нажмите
«Проверить снова». Кнопка «Очистить кэш» повторяет проверку, запрашивает подтверждение
и запускает удаление в фоне. «Остановить» прерывает работу между файловыми операциями;
уже удалённые файлы не восстанавливаются. Закрытие занятого окна запрашивает остановку;
после завершения операции окно можно закрыть. Журнал можно выделить и скопировать.

Требуется Windows с рабочим столом и **.NET Framework 4.8/4.8.1**.
Он включён в Windows 10 начиная с версии 1903 и Windows 11; для старых систем
наличие Framework нужно проверить отдельно. [Требования Microsoft](https://learn.microsoft.com/en-us/dotnet/framework/get-started/system-requirements).
Сборка AnyCPU работает в 32- и 64-битной Windows с указанным Framework.
Файл не подписан цифровой подписью. SHA-256 находится в `Clear-1CUserCache.exe.sha256.txt`.

EXE использует те же ограничения очистки, что описаны ниже, включая разрешение
`vrs-cache\cache.1CD`. WMI-проверка выполняется напрямую через `System.Management`.
Проверяются все сеансы текущей учётной записи; неопределённый владелец процесса
блокирует удаление. При ошибке WMI дальнейшее удаление останавливается.
Прогресс отражает число обработанных GUID-каталогов, а не байты.

Исходники и manifest — `onec-cache-cleaner/`. Сборка через PowerShell 7:

```powershell
pwsh -NoProfile -File .\onec-cache-cleaner\Build.ps1 -ReferenceDirectory C:\build\net48\build\.NETFramework\v4.8
```

`ReferenceDirectory` — каталог из официального NuGet-пакета
`Microsoft.NETFramework.ReferenceAssemblies.net48` версии `1.0.3`.
Для сборки используется Roslyn из PowerShell 7; эти компоненты не нужны пользователю EXE.

Проверка EXE: `pwsh -NoProfile -File .\tests\Test-1CUserCacheExe.ps1`.
На macOS пройдены тесты C#-движка: четыре расположения, исключения, `cache.1CD`,
readonly-файлы, ссылки, запрет произвольных путей, отмена и блокировка при имитации
запущенного клиента/сбоя WMI. Проверены сборка и PE/manifest.
Реальный интерфейс WinForms и прямую WMI-проверку нового EXE необходимо проверить
на Windows; проверка предыдущего CMD пользователем их не заменяет.

## Версия CMD

Для передачи пользователю нужен только **Clear-1CUserCache.cmd**. Это один файл
со встроенным PowerShell, без распаковки вспомогательных скриптов и скачивания компонентов.
Запуск — двойным щелчком под нужным пользователем, без «Запуск от имени администратора».
Требования: Windows 10/11 либо Windows Server с рабочим столом, Windows PowerShell 5.1,
доступ к CIM/WMI и разрешение корпоративной политики на выполнение такого кода.

1. Утилита проверяет процессы 1С и при необходимости предлагает закрыть их и нажать «Повтор».
2. Показывает имя пользователя, расположения и количество каталогов; запрашивает подтверждение.
3. Удаляет кэш и показывает результат. Пока идёт очистка, не запускайте 1С.

Обрабатываются только непосредственные подкаталоги с GUID-именами
(`xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`) в четырёх расположениях:

```text
%LOCALAPPDATA%\1C\1Cv8
%LOCALAPPDATA%\1C\1Cv82
%APPDATA%\1C\1Cv8
%APPDATA%\1C\1Cv82
```

Пути берутся из системных Known Folders учётной записи, запустившей утилиту,
включая перенаправленный Roaming. Профили других пользователей не перебираются.
Папки `1CEStart`, `licensing`, шаблоны и файлы непосредственно в корнях остаются.
Если внутри GUID-каталога найдены `1CEStart`, `licensing`, файлы `.lic`, `.1cd`
или ссылки/junction, весь этот каталог пропускается с сообщением.
Исключение — `vrs-cache\cache.1CD`: этот файл кэша удаляется вместе с каталогом.
Другие файлы `.1cd`, в том числе `1Cv8.1CD`, остаются защищёнными.
Ссылки в родительском пути также блокируют обработку. Список баз не удаляется.
Нестандартные пути, заданные параметром `/UC`, браузерный и серверный кэш не очищаются.

Проверяются `1cv8.exe` (включая Конфигуратор), `1cv8c.exe`, `1cv8s.exe`,
`1cv8t.exe` и `1cestart.exe`. Владелец определяется по SID, поэтому учитываются
другие сеансы того же пользователя. Процессы с установленным чужим SID не мешают.
Если владелец живого процесса недоступен или WMI не работает, очистка блокируется:
утилита не предполагает, что такой процесс безопасно игнорировать.
Процессы не завершаются принудительно.

Проверка повторяется после подтверждения и перед каждым каталогом.
Она не запрещает запуск 1С средствами ОС и не гарантирует отсутствие запуска
посреди удаления одного каталога. Закрывайте 1С до конца операции.
Заблокированные файлы и отказы доступа отображаются как ошибки; очистка может
оказаться частичной. Файлы удаляются без Корзины. Первый запуск 1С пересоздаёт кэш
и может быть дольше обычного; содержимое пользовательских GUID-каталогов Roaming
может включать локальное состояние, которое также будет сброшено.

Код возврата: `0` — успех, отсутствие кэша или отмена; `1` — ошибка выполнения;
`2` — неполная очистка. Подробности выводятся в консоль и итоговое окно.
`ExecutionPolicy Bypass` действует только на запускаемый PowerShell-процесс,
не меняет настройки Windows и не отменяет доменные политики/AppLocker/WDAC.

## Проверка

`tests/Test-1CUserCache.ps1` проверяет синтаксис встроенного payload и удаление
на временных каталогах: обе ветки, обе версии, GUID-фильтр, сохранение исключений,
лицензий и файлов баз, отказ от перехода по ссылкам.
В Windows запускайте тест через PowerShell 7 (`pwsh -NoProfile -File ...`).
Интерактивный запуск CMD, окна WinForms и проверку владельцев WMI нужно отдельно
проверить на Windows под обычной учётной записью, в том числе с открытым
Предприятием и Конфигуратором. На macOS эти Windows-компоненты недоступны.

Структура кэша и расположение списка баз: [документация 1С](https://its.1c.ru/db/content/metod8dev/src/admins/i8101591.htm).
